# 維護導覽：一次找到文字、說明、連結與圖片

## 修改前判斷

- 只改區段標題或輔助說明：修改 `config/siteContent.ts`。
- 改某一個程序的名稱、日期或適用身分：修改 `data/tasks.ts`。
- 改某一身分是否需要該程序：修改 `data/taskRules.ts`。
- 改電話、Email 或承辦人：修改 `data/contacts.ts`。
- 改 FAQ：修改 `data/content.ts`。
- 換圖：替換 `public/mascot/` 同名圖片，或修改 `config/mediaAssets.ts`。

## 網址分工

- `actionUrl`：直接執行作業，如繳費、宿舍申請、選課系統。
- `detailUrl`：官方說明、公告、PDF 或應備文件說明。
- `config/links.ts`：所有正式網址的唯一修改位置，包含頁首、必辦流程、FAQ 與校園生活。
- 未確認網址必須保持 `#contact` 或明確的待確認狀態，不可填搜尋引擎或非官方網址。

## 每年換學年度

1. 修改 `config/siteContent.ts` 的 `academicYear`。
2. 行政單位重新確認所有日期、網址、費用、資格與聯絡窗口。
3. 更新 `tasks.ts` 的 `verificationStatus` 及 `sourceNote`。
4. 執行 lint、build 與完整連結檢查。

## 新增身分

1. 在 `studentTypes.ts` 建立穩定的英文 id。
2. 在 `taskRules.ts` 為所有程序定義 requirement。
3. 若入學管道會改流程，再更新 `admissionTypes.ts`。
4. 使用桌機與手機測試新身分的必辦流程及條件任務。

## 新增程序

1. 在 `tasks.ts` 建立新 id 與完整欄位。
2. 在 `contacts.ts` 建立或指定 contactId。
3. 在 `taskRules.ts` 為每一種 student type 設定規則。
4. 在 `TaskSections.tsx` 的 `TASK_ICONS` 加入圖示。
5. 確認 actionUrl 與 detailUrl 不混用。

## 資料確認狀態

- `pending`：尚未取得正式回覆。
- `in_review`：承辦單位確認中。
- `confirmed`：已由資料負責單位正式確認。

建議每一筆 confirmed 資料都保留確認人、確認日期、依據來源與下次複核日期。正式 CMS 應保存變更紀錄，不只覆蓋最新值。
