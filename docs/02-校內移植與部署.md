# 校內移植與部署建議

## 建議架構

優先建議將此網站部署為獨立靜態站台，例如 `https://www.must.edu.tw/freshman/`，再從校首頁、招生頁或學生入口加上連結。這比把所有 React 程式直接貼進既有 CMS 頁面更容易維護、測試與回復版本。

## 三種掛載方式

### A. 獨立子目錄／虛擬目錄（建議）

- 設定 `NEXT_PUBLIC_SITE_BASE_PATH=/freshman`。
- 執行 `npm run build`。
- 將 `out/` 部署到 Web Server 的 `/freshman/`。
- 優點：效能佳、邊界清楚、容易回復版本。

### B. 反向代理到獨立站台（適合校內 DevOps）

- 原校網維持相同網域。
- `/freshman/` 由 Nginx／Apache／IIS 轉送到獨立靜態服務。
- 優點：可獨立發布，又能維持校方網域與憑證策略。

### C. iframe 嵌入（僅過渡使用）

- 必須檢查 CSP、X-Frame-Options、高度調整、鍵盤導覽及手機版。
- 可能造成雙重捲軸、SEO 與無障礙問題，不建議作為正式長期方案。

## 靜態建置

```bash
npm ci
npm run lint
npm run build
```

成功後部署 `out/`，不要部署 `node_modules/`、`.next/` 或原始碼到公開 Web Root。

## Web Server 必要設定

- MIME type：`.js`、`.css`、`.json`、`.png`、`.svg`、`.webp`。
- HTTPS 強制轉址。
- 壓縮：Brotli 或 gzip。
- Cache：含 hash 的 `/_next/static/` 可長期快取；`index.html` 應使用較短快取。
- 安全標頭：Content-Security-Policy、X-Content-Type-Options、Referrer-Policy、Permissions-Policy。
- 404：導向輸出的 `404.html`。

## 校內 API 與身分查詢

Prototype 不應直接從瀏覽器查詢正式招生資料庫。正式實作建議：

1. 由校內後端建立專用 API。
2. 僅回傳導覽所需的最少資訊，例如 studentTypeId、admissionTypeId。
3. 不在 localStorage 或日誌保留身分證號。
4. 加入輸入驗證、速率限制、存取紀錄、TLS 與個資影響評估。
5. 本版沒有身分證查詢；未來若新增身分辨識功能，應先經資訊安全及個資權責單位審核。

## 快取與更新

- 每次更新以完整 `out/` 原子替換，避免新舊 JS 混用。
- 建議保留前一版部署包，發生問題可立即回復。
- 年度重大更新前建立 staging URL 供行政單位驗收。
