# 資料治理與不同使用者管理建議

## 資料角色

| 角色 | 建議權限 | 主要責任 |
|---|---|---|
| 圖資中心系統管理員 | 部署、回復、環境設定 | 維護程式、主機與安全設定，不負責判斷校務內容 |
| 新生資訊總編 | 全站內容編修、送審 | 整合跨單位資料、控制首頁資訊量與用語一致性 |
| 業務單位編輯者 | 只能編輯自己負責的程序 | 提供日期、網址、資格、文件與聯絡窗口 |
| 業務單位審核者 | 核准／退回 | 確認資料可正式發布 |
| 稽核／唯讀者 | 檢視與匯出 | 查看來源、確認日期與歷史版本 |

## 建議發布流程

1. 業務單位編輯者填寫或更新資料。
2. 系統檢查必填欄位、網址格式與日期合理性。
3. 業務單位審核者確認。
4. 新生資訊總編檢查跨頁一致性與學生語言。
5. 圖資中心部署至 staging。
6. 相關單位驗收後發布 production。
7. 保存發布版本、操作者、時間及來源。

## 資料 Owner 原則

- 網站團隊負責整合與呈現，不應成為學費、資格、日期或法規的資料 Owner。
- 每個 Task 必須有 `dataOwner`。
- 每次確認至少記錄 confirmationStatus、confirmedBy、confirmedAt、sourceUrl。
- 重大日期建議設定自動到期提醒，避免沿用前一學年度資料。

## 未來 CMS 欄位權限

- 業務單位只能看到或修改自己擁有的 Task。
- 網址、日期與資格變更應要求審核。
- 已發布資料不可直接刪除，改為封存並保留歷史。
- 後台需使用校內 SSO、多因素驗證與最小權限原則。
